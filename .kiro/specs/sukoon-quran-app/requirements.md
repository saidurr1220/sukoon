# Requirements Document

## Introduction

Sukoon is a production-ready, mobile-first web application that provides users with carefully selected Qur'an verses (ayahs) based on their emotional state. The application features a unique jar reveal animation, optional daily email subscriptions, and strict safety protocols to ensure authentic Qur'an text rendering without any AI generation or modification.

## Glossary

- **Sukoon_App**: The complete web application system including frontend, backend, and database components
- **Verse_Selector**: The LLM-based component that selects verse IDs from candidate lists without accessing Qur'an text
- **Jar_Animation**: The hero animation sequence showing jar lid opening and paper slip rising to reveal the selected verse
- **Mood_Chip**: Interactive UI element representing emotional states (Happy, Sad, Angry, Anxious, Depressed, Grateful)
- **Verse_Card**: UI component displaying the complete ayah with Arabic text, translation, and audio controls
- **Email_Subscriber**: User who has opted in to receive daily ayah emails through double opt-in confirmation
- **Vetted_Dataset**: Pre-approved collection of Qur'an verses with verified Arabic text, translations, and metadata

## Requirements

### Requirement 1

**User Story:** As a user seeking spiritual comfort, I want to select my current mood and receive a relevant Qur'an verse, so that I can find appropriate guidance for my emotional state.

#### Acceptance Criteria

1. WHEN a user visits the landing page, THE Sukoon_App SHALL display six Mood_Chips representing Happy, Sad, Angry, Anxious, Depressed, and Grateful emotions
2. WHEN a user taps a Mood_Chip, THE Sukoon_App SHALL initiate the Jar_Animation sequence within 800 milliseconds
3. WHEN the Jar_Animation completes, THE Sukoon_App SHALL display a Verse_Card containing the selected ayah with Arabic text, translation, and audio controls
4. THE Sukoon_App SHALL render Arabic text using RTL direction with Amiri or Scheherazade fonts at appropriate size for mobile viewing
5. THE Sukoon_App SHALL include complete verse attribution showing Surah:Ayah reference, translator name, and audio credits

### Requirement 2

**User Story:** As a user concerned about Qur'an authenticity, I want assurance that the text is never modified or generated by AI, so that I can trust the spiritual content I'm receiving.

#### Acceptance Criteria

1. THE Sukoon_App SHALL never generate, summarize, paraphrase, or translate any Qur'an text using AI systems
2. THE Verse_Selector SHALL only receive verse_id candidates with weights and never access Arabic text or translations
3. THE Sukoon_App SHALL render all Qur'an content exclusively from the Vetted_Dataset without modification
4. THE Sukoon_App SHALL display a clear disclaimer stating it is not a tafsir or fiqh resource
5. THE Sukoon_App SHALL include proper attribution and licensing information for all translations and audio content

### Requirement 3

**User Story:** As a user who wants regular spiritual reminders, I want to subscribe to daily ayah emails, so that I can receive consistent spiritual guidance.

#### Acceptance Criteria

1. WHEN a user finishes reading a verse, THE Sukoon_App SHALL display a subscription popup asking "Get a daily ayah like this?"
2. WHEN a user enters their email address, THE Sukoon_App SHALL send a double opt-in confirmation email
3. WHEN a user confirms their subscription, THE Sukoon_App SHALL add them to the active Email_Subscriber list
4. THE Sukoon_App SHALL send daily emails containing one ayah with Surah:Ayah reference in the subject line
5. THE Sukoon_App SHALL include a one-click unsubscribe link in every email

### Requirement 4

**User Story:** As a mobile user, I want the app to work seamlessly on my phone with smooth animations, so that I can easily access spiritual content on the go.

#### Acceptance Criteria

1. THE Sukoon_App SHALL be optimized for mobile-first design with screens as narrow as 390 pixels
2. THE Sukoon_App SHALL implement the Jar_Animation using only transform and opacity properties for optimal performance
3. WHEN prefers-reduced-motion is enabled, THE Sukoon_App SHALL reduce animation durations to 0-50ms and disable rotation effects
4. THE Sukoon_App SHALL provide haptic feedback of 10ms duration when users tap Mood_Chips on supported devices
5. THE Sukoon_App SHALL meet PWA requirements with appropriate manifest and offline capabilities

### Requirement 5

**User Story:** As a user with accessibility needs, I want the app to be fully accessible with proper contrast and keyboard navigation, so that I can use it regardless of my abilities.

#### Acceptance Criteria

1. THE Sukoon_App SHALL maintain color contrast ratios of at least 4.5:1 for all text elements
2. THE Sukoon_App SHALL provide keyboard focus rings for all interactive elements
3. THE Sukoon_App SHALL support proper RTL text rendering for Arabic content without truncation
4. THE Sukoon_App SHALL ensure all interactive elements are at least 44px in size for touch accessibility
5. THE Sukoon_App SHALL achieve Lighthouse scores of 90 or higher for Performance, PWA, and Accessibility metrics

### Requirement 6

**User Story:** As a system administrator, I want the verse selection process to be transparent and auditable, so that I can ensure proper content curation and system reliability.

#### Acceptance Criteria

1. THE Verse_Selector SHALL only select from pre-approved candidate lists with assigned mood weights
2. THE Sukoon_App SHALL log all verse selections and email sends for audit purposes
3. THE Sukoon_App SHALL prevent sending duplicate verses to subscribers within 30 days
4. THE Sukoon_App SHALL use database transactions to ensure data consistency during subscription and email operations
5. THE Sukoon_App SHALL implement proper error handling and fallback mechanisms for all critical operations
